# Project Video0.2.0 qualification

This is an initial portable skill release, not a proven-best-workflow claim.
The package contains guidance, optional UI metadata, a fictional brief template
and a read-only FFmpeg export checker. It bundles no engine, private sources,
credentials, generated media, fonts or music. Optional corpus/publishing/voice
adapters are not mandatory dependencies and grant no resource access.

- Skill-creator structural validation; all package-relative reference links.
- Matching version/name/package metadata and shared-catalog validation.
- Python compilation of24 tracked skill/MCP sources, with generated bytecode
  outside the repository.
- Six checker integration tests using a generated actual H264/AAC recording:
  successful decode and read-only behavior; wrong duration/dimensions/frame rate;
  invalid media; missing tool; nonfinite expectation; relative colon filenames. All passed.
- Checker also accepted the actual30-second demo export with full decoding and

## Product comparison and independent forward test

A retained direct-Brag product film and an independent project-video run used
identical permitted input masters, central product claim, full-screen preference,
30-second1080x1920/30fps target and existing Hyperframes0.9.31 CPU toolchain.
The independent worker received only the package, input masters and user brief,
not the earlier output or desired composition. It completed one cut and one
focused correction in8m4s; its successful render took97.89s. Baseline case/delivery
timestamps bound a10m25s production interval, excluding earlier inspection.
Effort is approximate; these are not a controlled model-performance benchmark.

Both final files have900 H264/yuv420p frames and48kHz stereo AAC, fully decode,
and complete actual30-second headless browser playback with no errors. Real
source controls/save/reload support the claims; no physical/deployment or
cross-device result is inferred. Root review inspected output/phone/transition
frames. It found different editorial density and audio gain, not an established
quality winner: the independent mix is10.4LU quieter than the baseline. Sound
was measured, not heard; unfamiliar-viewer comprehension is not observed.

The forward test caught a practical resource issue: extraction of full-resolution
frames approached the256MiB budget. Cancelling that owned local render and
uniformly scaling the whole intermediate to actual stage pixels lowered the
observed working-set peak to152.23MiB. Original framing/master were preserved.
Production guidance now explains this failure mode and delivered-size typography.
Nine nonblocking engine editor-structure warnings remain in that test; the
standalone export passed. This is recorded, not hidden as a flawless run.

## Scope still unverified

Original physical-action footage, actual uptake on another being's receiving
runtime, human listening and first-view comprehension remain unverified. Existing
app/process/narrated trials do not fill those gaps. Initial public availability
must retain these limits; it does not complete the broader original production
and human-evaluation plan. Private trial media and task/account records are not
part of this package or a public release.

The exact selected package also passed describe/prepare/apply/status in a fresh
isolated installation root, reporting installed0.2.0 with matching bytes. Its

This proves a clean local installation, not adoption by another being.
